# ProDesk 6.15.1

Base: `aa2722175fa044e238ad524fefb28f1e56ef223e` (6.15.0).

## Behavior

- Recent-task navigation no longer cancels its own first page load on a redundant hashchange. Changed page IDs still invalidate stale responses.
- Task creation, completion and document commands reconcile task lists and metrics instead of running the eight-request global bootstrap. Regular completion uses two parallel reconciliation requests (card metadata can be requested separately by the UI).
- Reopening an old completed task retains the existing idempotent carry-over to Today. This exceptional path still calls task_rollover; it does not initialize profiles, repeat generation or legacy datasets.
- Failed writes roll back optimistic completion; a failed read after a committed write does not revert the saved operation. Task command errors distinguish these cases, and uncommitted commands support the cloud retry control.
- The mounted task inspector follows the confirmed schedule date without overwriting a pending or failed date edit. The schedule popover is anchored within narrow viewports.
- Working-list rows without actions no longer render an empty menu; usable library menus support Escape.
- QA Sandbox implements goal_rollup_get/save locally: numeric/duration fields, linked-task sums, target validation, upsert/removal and persistence. Existing local sessions are compatible.
- Vite is pinned to 7.3.7; esbuild is updated transitively. Node requires 20.19+ in the 20.x line or 22.12+. CI uses the existing Node 22 setup and npm ci for reproducible lockfile installs.

## Validation

- `npm run build` (TypeScript + Vite); existing oversized-chunk warning remains, not a build failure.
- All `tests/*.mjs`, including the new executable QA rollup regression.
- `npm run test:qa` with the new navigation, date, menu, failure, capture and rollup scenarios. Real viewport sizes in Chromium: 320, 390, 430 and 1440 CSS px, including page overflow and popover boundaries.
- `npm audit --json`: no advisories at patch preparation time. This is a dependency check, not proof of application security.
- E2E production API calls are intercepted/blocked; tests use disposable local QA data. The patch-specific transport instrumentation is test-only.

Actual execution results and current-head CI are recorded in the PR. A historical version assertion was updated for 6.15.1. An initial concurrent test run collided on trace output; final regression runs must use a single process/output directory.

## Data, deployment and rollback

No database migrations, production writes, Edge Function deployments, authentication or RLS changes are required. Existing task IDs, page contents, goal links, categories, income and stored local QA data are retained. The goal progress redesign and new product features are outside this patch.

Real Telegram iOS/Android keyboard, safe areas, haptics and authenticated production CRUD are NOT RUN. Perform these acceptance checks separately after a release is authorized. A browser viewport is not a physical-device check.

Before release, verify both current-head CI checks and review the patch. Merge/deploy is a separate operation; this change does not authorize a production backend deployment. Rollback: revert this PR and rebuild the static frontend; no data reversal is needed.
