# Personal OS 6.2 — Pages, Databases, Split Pipeline

Это обновление **существующего React-проекта 6.1**, а не замена Supabase или Telegram-бота.

## Что добавлено

- Страницы с вложенностью, иконками, постоянными ссылками `#/page/<UUID>`.
- Упорядоченные блоки: текст, заголовок, чеклист, изображение через HTTPS-ссылку, разделитель, ссылка на страницу, встроенная база данных, Split Pipeline.
- Data Source с полями Text, Number, Status, Date, Checkbox, Select и Relation. Каждая запись имеет собственную страницу с блоками.
- Представления одной базы: Table, Board, List, Calendar. Виды используют **те же записи**, а настройки сортировки и фильтров сохраняются отдельно.
- Split Pipeline: последовательность этапов (Split), вертикальные действия (Workflow), галочки, локальный и общий прогресс, редактирование порядка.
- Десктоп: локальная горизонтальная полоса Split. Телефон: выбор Split вкладками, отображается чеклист одного этапа; документ не прокручивается по горизонтали.
- Безопасная серверная авторизация через Telegram initData, изоляция данных по подтверждённому Telegram ID.

## Установка, не затрагивая работающую Personal OS

**0. Перед началом**

1. Сохрани текущий GitHub-репозиторий через `Code → Download ZIP` и экспортируй важные таблицы Supabase.
2. Этот релиз собран на базе последнего переданного исходника Personal OS 6.1. Если после него ты менял код, сравни изменения и не перезаписывай свои доработки вслепую.
3. Токены и секреты никогда не вставляй во frontend и не присылай в чат.

**1. Миграция базы**

1. Открой Supabase → SQL Editor → New query.
2. Выполни файл `supabase/03-workspace-schema.sql`.
3. В Table Editor появятся 8 таблиц: `os7_pages`, `os7_blocks`, `os7_data_sources`, `os7_fields`, `os7_records`, `os7_views`, `os7_splits`, `os7_workflow_items`.
4. Существующие таблицы `profiles`, `daily_stats`, `personal_tasks`, `ambitious_goals`, `goal_history` и все таблицы os6/os61 **не меняются**.

**2. Новая Edge Function (не вместо старых)**

1. Supabase → Edge Functions → Deploy a new function → Via Editor.
2. Имя: `os7`.
3. Замени содержимое редактора `index.ts` на файл `supabase/04-os7-index.ts`.
4. Нажми Deploy.
5. У `os7` выключи **Verify JWT**, только если оставил без изменений серверную проверку подписи Telegram `verifyTelegram()` в коде. Наша функция отказывает в доступе без валидного initData.
6. Убедись, что секрет `TG_BOT_TOKEN` у Supabase относится именно к боту, через которого открывается Mini App; повторно вставлять в GitHub его нельзя.
7. Не удаляй и не изменяй `dashboard`, `os6`, `os61`, `telegram-webhook`, `os6-jobs`.

**3. Обнови frontend**

Полный React-проект лежит в архиве в папке `Personal_OS_6_2_Workspace/`. Для проекта React необходимо обновить **все изменённые файлы**, а не только один `index.html`.

Через сайт GitHub:

1. Открой `VanyaMars/telegram-dashboard`.
2. Через `Add file → Upload files` загрузи новые папки `src`, `supabase`, `tests` и конфигурационные файлы, при необходимости заменяя одноимённые через кнопку карандаша на страницах файлов.
3. Если GitHub не загрузит скрытую `.github`, открой существующий `.github/workflows/deploy.yml` на сайте и добавь шаг `npm run test:workspace` после smoke-тестов; само наличие нового workflow не требуется, если уже есть рабочий.
4. Проверь, что `src/pages/Workspace.tsx`, `src/components/WorkspacePipeline.tsx`, `src/components/WorkspaceDatabase.tsx`, `src/pages/workspace.css` оказались внутри `src`, а не вложенной папки с названием релиза.
5. Нажми Commit changes.
6. В GitHub → Settings → Pages → Source выбери GitHub Actions. В Actions проверь, что сборка стала зелёной. Красная сборка — не считать релиз установленным.
7. Полностью закрой Mini App в Telegram и открой заново.

**4. Приёмочный сценарий**

1. В боковой панели появится пункт `Страницы`.
2. Создай страницу `Разработать сайт`.
3. Вставь блок `Split Pipeline`, добавь Split `Планирование`, `Разработка`, `Запуск`.
4. Добавь в первый Split три пункта, отметь один. Он должен показать **33%**. В мобильной версии выбирай другие Split по вкладкам.
5. Добавь блок `База данных`, создай источник `Проекты`, добавь поле `Статус` и запись. Проверь, что запись открывается как самостоятельная страница.
6. Переключи представления Table / Board / List / Calendar и проверь, что запись не дублируется.
7. Закрой и открой Mini App, затем открой его со второго устройства с тем же Telegram-аккаунтом. Данные должны сохраниться.
8. Проверь старые `Сегодня`, `Буфер`, `Цели`, `Аналитика`, `Финансы`, `Спорт` и сообщения Telegram webhook.

## Ограничения первого рабочего варианта

- Блок Image добавляет изображение по HTTPS-ссылке, **не загружает файл в Supabase Storage**.
- Изменять порядок блоков, Split и пунктов Workflow можно кнопками; жестовое перетаскивание именно этих новых элементов не добавлено.
- Перенос Workflow-пунктов **между** Split пока не реализован.
- Список источников ограничен 300, дерево страниц — 500, выдача записей — до 2000 на встраиваемую базу. Для больших коллекций нужна постраничная навигация на сервере.
- Текстовый редактор первой версии — обычный текст и заголовок; это не полный rich-text Notion.
- В режиме `?demo=1` просмотр пространства отключён от облака; полноценное сохранение работает в Telegram Mini App после миграции и создания os7.

## Безопасность / архитектура

- GitHub Pages: статический React/Vite frontend.
- Edge Function `os7`: Telegram HMAC-проверка `initData`, контроль `telegram_user_id`, перечень разрешённых операций.
- Supabase Postgres: восемь новых таблиц с composite FK владельца, включённой RLS и запретом прямого доступа `anon/authenticated`.
- UUID для новых объектов. JSONB используется только для блоков, полей записей и конфигурации представлений.
- Никакие service-role ключи не передаются клиенту.
- В перспективе агентам можно предоставить **ограниченный** набор серверных операций после отдельной авторизации, но сейчас ИИ-агент не реализован.

## Откат

Верни прежний `src` и связанные файлы из сохранённого ZIP или GitHub history. `dashboard`, `os6`, `os61` не менялись. Новые `os7_*` таблицы и функция могут остаться неиспользуемыми; **не удаляй их без отдельного резервного копирования**.
