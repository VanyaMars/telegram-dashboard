# Personal OS 6.1 — Premium UI

Полный исходный проект Telegram Mini App: **React 18 + TypeScript + Vite**, GitHub Pages и существующая Supabase. Светлая тема с деликатным «стеклом», боковым меню, новой главной, постоянными категориями, правильным часовым поясом и перетаскиванием задач.

**Что сохраняется:** существующие `dashboard`, `os6`, `telegram-webhook`, `os6-jobs`, таблицы `profiles`, `daily_stats`, `personal_tasks`, `ambitious_goals`, `goal_history` и таблицы 6.0. Никакие пользовательские записи не должны удаляться при миграции 6.1. Сообщения боту продолжает принимать старый webhook. Cron по-прежнему можно оставить неактивным.

**Бесплатно:** GitHub Pages + Supabase Free в пределах лимитов. Сама разработка не предполагает платных API.

## Что нового

- Светлый Apple-подобный UI: графитовый текст, белые glass-карточки, фиолетово-лавандовые/мятные/персиковые акценты; адаптация под мобильный Telegram и десктоп.
- В верхней панели: бургер, название текущего экрана, статус облака, справка. Версия переехала в низ меню и под список на мобильном.
- Нижняя панель: **Главное / Сегодня / Цели / Аналитика**. Буфер, календарь, завтра, финансы, спорт, фокус, вызовы, повторения, дисциплина, обзор недели, категории и настройки — в боковом меню.
- Страница «Главное»: показатель до 200%, недельные KPI, важные задачи, цели, финансы, тренировки, недельный график.
- «Сегодня» использует часовой пояс профиля (IANA) и автоматически меняет текущую дату при полуночи; другие выбранные даты не сбрасывает.
- Задачи можно переставлять удержанием ручки на телефоне / мышью на компьютере, с переносом между важными и дополнительными, а также в буфер через меню. Порядок хранится в PostgreSQL на пользователя. Дополнительно: ArrowUp/ArrowDown на сфокусированной ручке.
- Постоянные категории: создать, изменить название, иконку и цвет, переставить, удалить без удаления связанных задач; старые значения сферы импортируются.
- Сохраняются финансовый и спортивный модули, фокус, повторы, вызовы, недельные обзоры, связи задач с целями, KPI и аналитика.

## Самое важное: версия 6.1 устанавливается иначе, чем 5.0/6.0

**Недостаточно загрузить один `index.html` в GitHub.** React/Vite требует сборки. В архиве находится *весь проект* вместе с файлом `.github/workflows/deploy.yml`, который автоматически собирает и публикует сайт при обновлении репозитория. Адрес останется тем же: `https://vanyamars.github.io/telegram-dashboard/`.

## Установка по шагам

### Шаг 0. Резервная копия

1. В GitHub открой репозиторий `VanyaMars/telegram-dashboard` и сохрани номер последнего рабочего коммита; при возможности скачай старую версию ZIP через **Code → Download ZIP**.
2. В Supabase → Table Editor сделай резервный CSV-экспорт значимых таблиц (`profiles`, `daily_stats`, `personal_tasks`, `ambitious_goals`, `goal_history`, финансовых записей и т. д.). CSV — удобная страховка содержимого, но не полный дамп БД со связями. Для полного бэкапа используйте `pg_dump`.
3. Не удаляй старые Edge Functions, не очищай старые таблицы и не меняй бот-токен.

### Шаг 1. Новые таблицы и поля (Supabase)

1. Supabase → свой проект → **SQL Editor → New query**.
2. Открой файл `supabase/01-migration.sql`, скопируй его *целиком* в редактор.
3. Нажми **Run**. При `Success` в Table Editor появятся `os61_categories` и `os61_preferences`; таблица `personal_tasks` получит два новых столбца `os61_category_id`, `os61_position`.
4. При любой ошибке остановись, сохрани текст ошибки, **не пытайся перезаписать** старые таблицы.

SQL — добавочная миграция: он создаёт категории и копирует старые значения `sphere` в справочник, не переписывая названия/даты/факт выполнения задач или историю KPI.

### Шаг 2. Новая функция `os61` (Supabase)

1. **Supabase → Edge Functions → Deploy a new function → Via Editor**.
2. Имя: строго `os61` (без пробелов и тире).
3. Открой `index.ts` и полностью замени содержимое кодом файла `supabase/02-os61-index.ts`.
4. Нажми **Deploy function**.
5. Для **этой** функции выключи **Verify JWT** — в самом `os61` проверяется Telegram `initData` по HMAC и `TG_BOT_TOKEN`, как в остальных функциях проекта.
6. Убедись, что в **Edge Functions → Secrets** ранее созданный `TG_BOT_TOKEN` относится к вашему боту. Никуда не отправляй сам секрет.
7. Уже работающие `dashboard`, `os6` и `telegram-webhook` **НЕ меняй**.

### Шаг 3. Загрузка всего React-проекта в GitHub (без Terminal)

На Mac удобнее всего с **GitHub Desktop**:

1. Установи/открой [GitHub Desktop](https://desktop.github.com/), войди в тот же GitHub-аккаунт.
2. **File → Clone Repository** → выбери `VanyaMars/telegram-dashboard` → **Clone**.
3. В GitHub Desktop выбери **Repository → Show in Finder**: откроется папка твоего существующего репозитория.
4. Распакуй архив 6.1 в другую папку. **Скопируй содержимое папки проекта**, а не саму папку, в папку клонированного репозитория. Замени `index.html`, добавь `src`, `supabase`, `package.json`, `vite.config.ts`, `tsconfig.json`, `tests`, `.github/workflows/deploy.yml` и остальные файлы. Старые файлы без необходимости не удаляй.
5. Чтобы видеть скрытую папку `.github`, нажми в Finder **⌘ + ⇧ + .** (Command + Shift + точка). Она обязательна — без неё автоматическая публикация не запустится.
6. Вернись в GitHub Desktop. В списке изменений должны быть **многие файлы**, включая `.github/workflows/deploy.yml`, а не только `index.html`.
7. Введи commit message `Personal OS 6.1 Premium UI` → **Commit to main** → **Push origin**.

### Шаг 4. Включи GitHub Actions для Pages

1. На GitHub открой `VanyaMars/telegram-dashboard` → **Settings → Pages**.
2. **Build and deployment → Source → GitHub Actions**. **Не** `Deploy from a branch`: React теперь должен собираться перед публикацией.
3. Открой вкладку **Actions** → workflow `Publish Personal OS 6.1` и дождись *зелёного* успешного завершения. Там выполняются `npm install`, `npm run test:smoke`, `npm run build`, затем публикация `dist/`.
4. Если Actions красный, **не удаляй/не обнуляй Supabase**; открой неуспешный шаг и сохрани текст ошибки. Часто это сборка проекта, которую можно исправить отдельным коммитом.
5. Открой `https://vanyamars.github.io/telegram-dashboard/?demo=1`, чтобы посмотреть демонстрационную тему в браузере. Демо-данные не записываются в твою базу.
6. Полностью закрой Mini App в ProDesk → открой заново. Проверь настоящие данные и синхронизацию с MacBook.

GitHub Pages может не показывать новую сборку немедленно; её статус виден на вкладке **Actions**. Если по ошибке опубликовал один `index.html` без `src`, сайт не запустится — нужны все файлы и workflow.

## Проверка после установки

1. «Главное» → недели, цели, финансы и спорт загрузились; старые записи не пропали.
2. «Сегодня» → убедись в правильной сегодняшней дате и часовом поясе из **Настроек**.
3. Создай одну важную и пять дополнительных задач → после выполнения 1 + 3 результат должен быть **160%**, после всех дополнительных **200%**.
4. Перетащи задачу за ручку, затем перейди в другой раздел и обратно → порядок сохранился. Проверь на втором устройстве. Альтернатива: перетащи мышью или используй контекстное меню.
5. Бургер → Категории → создай новую, переименуй и измени цвет → создай задачу этой категории → убедись, что после перезагрузки она сохранена.
6. Буфер → новая задача → она не должна попасть в сегодняшний список, пока её туда не перенести.
7. Финансы, спорт, цели, календарь, фокус, вызовы → открой и проверь старые данные.
8. Напиши боту ProDesk задачу в сообщении. Она должна появиться в буфере через уже работающий webhook — мы его не заменяем.

## Локальная разработка

Если понадобится развивать приложение на Mac с Node.js 22+:

```bash
npm install
npm run test:smoke
npm run build
npm run dev
```

Приложение на `http://localhost:5173` без Telegram `initData` показывает сообщение об авторизации. Для **визуальной проверки интерфейса** используй `http://localhost:5173/?demo=1` (без обращения к пользовательской базе). Демонстрационный режим **не предназначен для рабочих данных**.

## Откат без потери данных

Если новый интерфейс не работает, верни предыдущий GitHub commit и восстанови прежний способ GitHub Pages-публикации (вкладка Settings → Pages). Функции `dashboard`, `os6`, `telegram-webhook` не менялись и останутся доступными версии 6.0. **Не запускай обратную SQL-миграцию, которая удаляет новые таблицы:** дополнительные таблицы безвредны и могут содержать внесённые после 6.1 изменения.

## Безопасность

- Frontend содержит только **публичный** URL Supabase. `TG_BOT_TOKEN`, `SUPABASE_SERVICE_ROLE_KEY`, секрет webhook и JWT ни в коем случае не добавлять в репозиторий.
- `os61` проверяет Telegram `initData`, дату авторизации, идентификатор владельца; защищает мутации категориями и задачами; SQL выдаёт доступ к RCP-функциям только `service_role`.
- Экран `?demo=1` локален и не читает реальную статистику.
- Стабильность автоматических уведомлений всё ещё зависит от отдельно отложенной настройки Cron; данный пакет её **не включает**.

## Пределы тестирования этого релиза

Локально проверены статический визуальный макет (ширины 320/390/1440 px), синтаксис TS/TSX, базовые формулы дат и прогресса, структура миграции, отсутствие публичных секретов. **Полный React build не удалось выполнить в этом окружении из-за недоступности npm-реестра; GitHub Actions выполняет обязательные `test:smoke` и `npm run build` перед публикацией.** Подключение к реальному Supabase, drag-and-drop в настоящем Telegram-клиенте, все 14 модулей и фактическая сборка пока требуют проверки при установке.
