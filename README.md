# Personal OS 6.3 — задачи-страницы и единые цели

**Не новый проект:** обновление React + TypeScript + Vite приложения Personal OS 6.2. Старые задачи (`personal_tasks`), амбициозные цели (`ambitious_goals`), блоки и Pipeline (`os7_*`), Telegram-авторизация и остальные данные сохраняются.

## Что меняется

- **Боковое меню:** финансовый, спортивный и категорийный экраны скрыты из навигации, но их данные и серверные функции **не удаляются**.
- **Цели:** амбициозные цели остаются со старой историей и формулой; обычные цели имеют период `Бессрочная / Неделя / Месяц / Со сроком`, описание и редактируемый прогресс 0–100%. Данные обычных целей едины для «Главное» и «Цели».
- **Буфер задач + Страницы:** объединены в одной навигационной вкладке. Каждая запись `personal_tasks` имеет постоянную страницу `os7_pages` через таблицу связей `os8_task_pages`. Дата, категория, тип, заметка и состояние выполнения остаются в `personal_tasks`. Внутри страницы доступны блоки, чеклисты, базы и Split Pipeline из версии 6.2.
- **Синхронизация:** новые задачи, включая отправленные ботом и созданные повторением, автоматически получают страницы. При миграции создаются страницы для старых задач; название автоматически синхронизируется в обе стороны.
- **Прогресс:** число по-прежнему 0–200% (100 за важные + 100 за дополнительные), но визуально **одна** шкала шириной 0–100% исключительно по важным задачам. После выполнения важных задач она фиолетовая; за дополнительные постепенно становится фиолетово-розовым градиентом; при 200% — фуксия с деликатной анимацией (для reduced motion отключена).
- **Pipeline:** на ПК и планшетах горизонтальные столбцы; на телефоне вертикальный стек всех этапов без бокового скролла всей страницы.

## Установка в существующий проект (порядок важен)

### 0. Резервная копия

- В GitHub сохраните предыдущий commit / Download ZIP. **Не удаляйте** старые файлы до публикации новой версии.
- Экспортируйте важные таблицы Supabase, включая `personal_tasks`, `ambitious_goals`, `os7_pages`, `os7_blocks`, `os7_splits`, `os7_workflow_items` и `profiles`.
- Убедитесь, что 6.2 уже работает: Edge Function `os7` опубликована и SQL `03-workspace-schema.sql` был выполнен.

### 1. SQL — **обязательно до публикации интерфейса**

Supabase → SQL Editor → New Query → откройте `supabase/05-os8-unified.sql` → вставьте **весь** код → Run.
Миграция только добавляет структуры, триггеры и ссылки. Старые задачи и цели не удаляет, повторный запуск не должен создавать дубликаты страниц.
Проверьте наличие `os8_regular_goals`, `os8_task_pages` и отсутствие ошибок SQL.

### 2. Edge Function `os8`

Supabase → Edge Functions → Deploy a new function → Via Editor → имя **`os8`**. Замените `index.ts` кодом из `supabase/06-os8-index.ts`, нажмите Deploy. Для **этой** функции выключите `Verify JWT` (OFF), поскольку она проверяет Telegram HMAC и время `initData` самостоятельно. Убедитесь, что общий секрет `TG_BOT_TOKEN` принадлежит действующему боту. **Никогда не размещайте секрет во фронтенде или GitHub.**

Функции `dashboard`, `os6`, `os61`, `os7`, `telegram-webhook` и `os6-jobs` **не заменять**. Новый интерфейс использует их вместе с `os8`.

### 3. GitHub

Откройте `https://github.dev/VanyaMars/telegram-dashboard` через браузер, перетащите **содержимое** этой папки релиза в **корень** существующего репозитория (не вложенную папку). Перезапишите файлы `src/`, `tests/`, `package.json`, `index.html`, `.github/workflows/deploy.yml` и прочие новые исходники. Не трогайте GitHub-секреты и скрытую папку `.git`, если работаете локально.

Source Control → напишите `Personal OS 6.3 unified goals and task pages` → Commit & Push.

GitHub → Settings → Pages: Source = **GitHub Actions**. В Actions процесс `Publish Personal OS 6.3` должен закончиться зелёной галочкой. Убедитесь, что **Compile and build** прошёл, а не только тесты.

### 4. Проверка внутри Telegram

1. Откройте ProDesk → Буфер задач: старые задачи на месте.
2. Нажмите на название задачи: откроется её **страница** со свойствами и блоками.
3. Внутри страницы добавьте Split Pipeline, два этапа и чеклист. Обновите приложение: всё должно сохраниться.
4. Измените название страницы и вернитесь в Буфер: название задачи должно совпадать.
5. Измените категорию, тип или дату на странице и проверьте «Сегодня».
6. Создайте обычную цель со сроком: она должна появиться и в «Целях», и на «Главном».
7. В «Сегодня» отметьте 1 важную и 3 из 5 дополнительных: **160%**, заполненная шкала с градиентом. Отметьте все 5: **200%**, фуксия.
8. На смартфоне Split Pipeline идёт **сверху вниз**, а на ПК — **слева направо**.
9. Проверьте вход и синхронизацию с MacBook и смартфона.

## Важные границы версии

- Обычные цели сохраняют выбранный период и даты; **автоматическое создание нового экземпляра каждую неделю/месяц здесь не включено**, его можно добавить отдельно.
- Числовой прогресс обычной цели редактируется вручную; он не меняет амбициозные цели и не подменяет фактические результаты.
- Процесс создания страниц старых задач — безопасный backfill и триггер, но **не испытан на реальной базе**: перед SQL обязательно сделайте экспорт.
- Старые разделы «Финансы», «Спорт», «Категории» скрыты из меню, но записи и API остаются нетронутыми.
- Не подтверждена реальная production-сборка: npm в этой среде недоступен. GitHub Actions должен выполнить `npm install`, тесты, `tsc --noEmit`, `vite build`.

## Откат

В GitHub верните предыдущий коммит 6.2. Функцию `os8` и новые таблицы можно оставить: они не заменяют существующие таблицы или методы. Не выполняйте `DROP TABLE`, не удаляйте SQL-триггеры вслепую. При откате UI 6.2 продолжит читать прежние таблицы задач и целей.
